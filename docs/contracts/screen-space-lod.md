# Screen-space LOD selection

`three-d-lod` owns both halves of static level of detail: deriving simplified index buffers (`build_lod_chain`) and choosing which level to show (`ScreenSpaceLodPolicy`). Renderers and the web lab consume those decisions; they do not re-derive them.

## Selection semantics

- Each level has an object-space geometric error. Level 0 is the source mesh with error `0`. Errors must be finite, non-negative, and nondecreasing toward coarser levels. For meshopt output, geometric error is `relative_error × mesh_extent`, where `mesh_extent` is the largest bounding-box axis.
- `LodView` projects an error into pixels: `error × viewport_height / (2 × distance × tan(fov_y / 2))`. Distance is measured from the camera to the mesh bounds centre.
- The ideal level is the coarsest level whose projected error is at most the pixel budget `B`.
- With hysteresis fraction `h` (`0 ≤ h < 1`) and the level shown in the previous frame `c`:
  - if `c` projects above `B × (1 + h)`, refine to the ideal level;
  - otherwise, coarsen to the coarsest level at or below `B × (1 − h)` if it is coarser than `c`;
  - otherwise keep `c`.
- With `h = 0`, the selected level always equals the ideal level. Each decision reports `kept`, `coarsened`, or `refined`.

Camera policy, such as which distance to use for off-centre or multi-object scenes, stays with consumers.

## Web evidence

`fixtures/lod/screen-space-lod.json` is generated by `cargo run -p three-d-lod --example screen_space_lod_evidence`. It contains the teaching mesh, every level's index buffer, and, for each offered viewport height (360, 540, and 720 CSS pixels), projected errors on a fixed distance grid plus, for each offered budget and hysteresis setting, the selected level for every previous level. The `screen_space_lod_evidence` integration test fails when the committed file drifts from the crate.

The `/lod/` lab only looks decisions up in that document, carrying the shown level from one interaction to the next. It never projects errors, applies hysteresis, or simplifies meshes.

### Viewport height

Projected error is proportional to viewport height, so decisions made for one height are wrong for a canvas of another height. Rather than rescale errors or budgets in TypeScript, which would duplicate projection semantics outside Rust, the lab renders at a height Rust evaluated: it takes the space available (72% of the window height), snaps the canvas to the tallest offered height that fits (or the shortest when none fits), sets that exact CSS content height, and looks up the tables for it. Resizing re-snaps the canvas and re-looks up the decision in the new height's tables, carrying the shown level. Heights are CSS pixels; device pixel ratio changes sharpness, not the projection. Supporting another height means adding it to `VIEWPORT_HEIGHTS_PIXELS` and regenerating the evidence.

`scripts/lod-browser-smoke.mjs` checks in Chromium that exact distance entry and viewport dolly drive the same state, that the canvas draws the selected index buffers, and that the drawn canvas height equals the evidence height in use, including after resizing to a short window that snaps to the 360 px tables.

## Out of scope

Appearance-aware error metrics for normals, UVs, and colors; compact per-level vertex buffers; and deformation-aware simplification for skinned meshes.
